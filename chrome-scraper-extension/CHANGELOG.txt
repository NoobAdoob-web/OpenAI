========================================================================
  SCRAPESUITE  --  CHANGELOG
========================================================================
The version is shown in the popup header and set in manifest.json.
Downloaded builds are named: chrome-scraper-extension-vX.Y.Z.zip


------------------------------------------------------------------------
v2.10.1  (current)
------------------------------------------------------------------------
- FIX: "Could not decode image: 'icon.svg'" on the Chrome Web Store, which
  left the listing spinning and blocked Add to Chrome. Chrome extensions do
  NOT support SVG icons - manifest "icons" and "action.default_icon" must be
  raster PNG. Shipped real PNG icons at 16/32/48/128 (rendered from the same
  artwork) and pointed the manifest and popup header at them.

------------------------------------------------------------------------
v2.10.0
------------------------------------------------------------------------
- POST COPY / DESCRIPTION for every post. On a reels or posts GRID the
  caption is never rendered into the tile, which is why the Caption column
  came back empty for every row. ScrapeSuite now reads the post copy from
  the data the page itself already loads: a small hook runs in the page and
  observes Instagram's / Facebook's own API responses (read-only, nothing
  is requested or sent anywhere) and hands over the caption per post.
  The same source also fills:
    * Date      (exact upload date - was blank on 98% of rows)
    * Duration  (real video length, e.g. 0:15 - was blank on 100% of rows)
    * EXACT counts (85700 rather than the grid's rounded "85.7K"); the
      numeric columns now carry the precise value for analysis.
  No extra page loads and no Deep Scrape needed - captions arrive as you
  scroll. Deep Scrape still fills anything the API did not provide.
- URL and Thumbnail columns are now pinned to the FAR RIGHT of the preview,
  CSV and both Excel tabs, so the readable content comes first.

------------------------------------------------------------------------
v2.9.2
------------------------------------------------------------------------
- OCR tuning round driven by real scraped data (204 rows) + annotated
  feedback. Measured on a hard, realistic test set (text over video-like
  backgrounds, wide letter-spacing, translucency, motion blur, small strap
  lines): accuracy 96.9% -> 98.4%, no empty results.
  * Source is upscaled to ~1280px before OCR - this is what recovers word
    spaces on SMALL on-image text ("PoweredbySnapdragon" -> "Powered by
    Snapdragon customized for Galaxy").
  * Detection now runs at 1280px (was capped at 960px).
  * Latin-only output mask: stops stray Chinese glyphs (e.g. a lone CJK
    character) appearing in Image Text, since the bundled model is the
    Chinese PP-OCRv4 model.
- Known model limit: capital "I" vs lowercase "l" are identical glyphs in
  most sans fonts, so "Bespoke AI" can read as "Bespoke Al".
- IMPORTANT: reels keep most of their text in the VIDEO, not the cover
  image. Cover-only OCR therefore misses it (22% of rows came back empty).
  Multi-frame video reading is the next step.

------------------------------------------------------------------------
v2.9.1
------------------------------------------------------------------------
- OCR accuracy pass on the bundled PP-OCRv4 model (no model change):
  * Word spacing: text lines are now recognised as whole merged lines with
    generous padding + synthetic margins, so the model emits spaces
    natively. Fixes "UsecodeSAVE20" -> "Use code SAVE20".
  * Edge letters no longer clipped (fixes "ntroducing" -> "Introducing").
  * Small thumbnails are upscaled before OCR for better recall.
  Verified on stylised marketing samples: "MEGA SALE", "Shop Now - Limited
  Time", "Buy 1 Get 1 Free", "Introducing the new" all read correctly with
  spaces (95-100%). Note: reels with text burned into the VIDEO (not the
  cover image) still need video-frame sampling — coming next.

------------------------------------------------------------------------
v2.9.0
------------------------------------------------------------------------
- New OCR engine: image reading now uses PaddleOCR PP-OCRv4 (text detection
  + recognition) running on onnxruntime-web (WASM), fully on-device. This is
  a big accuracy jump over the previous engine on stylized marketing text —
  coloured/decorative fonts on busy backgrounds, e.g. reel thumbnails and
  posters. Detection post-processing is a light connected-components pass
  (no OpenCV), so the engine has no eval/new-Function and runs under the
  extension's strict CSP.
- Scope: reads ENGLISH / Latin script. (The previous build also attempted
  Hindi via Tesseract; the Devanagari PP-OCR model is a planned add-on.)
- Verified end-to-end against sample marketing graphics: coloured headline +
  offer text read correctly at 95-100% confidence.
- Bundle grows (~+15 MB: models + WASM runtime) — the cost of accurate,
  private, on-device OCR with no API keys or backend.
- Removed the bundled Tesseract engine and language packs.

v2.8.1
------------------------------------------------------------------------
- Removed broad "<all_urls>" host permission (which forced a slow Chrome Web
  Store in-depth review). The extension now requests access ONLY to the sites
  it supports: YouTube, Instagram, Facebook, LinkedIn, Amazon (all major
  marketplaces) and Flipkart. Content scripts are scoped to the same sites.
  Trade-off: it no longer runs on arbitrary websites, only these platforms.

v2.7.1
------------------------------------------------------------------------
- Fix exact date range (Instagram etc.): the per-post date read now tries
  many sources — any <time> datetime/title, JSON-LD datePublished/uploadDate,
  embedded taken_at/creation_time timestamps, meta tags, then text — so dates
  come through where they previously came back blank.
- Instead of only the first & last post, it now samples 5 posts (first, ~25%,
  ~50%, ~75%, last) for a directional read; the analysis shows a "Sampled
  dates" line plus the first/last dates and the overall range.

------------------------------------------------------------------------
v2.7.0
------------------------------------------------------------------------
- Collect reviews by star (Amazon): on an Amazon product/reviews page a new
  section lets you set how many 5★/4★/3★/2★/1★ reviews you want (0 = skip).
  The extension opens Amazon's star-filtered review pages in the background
  and pages through them until each target is met (or Amazon runs out),
  collecting the maximum available. Live progress per star; Stop anytime.
  Results replace the table and export as usual (ranked by helpful votes).
  Note: Amazon limits very deep pagination, so huge targets may stop early
  at what's actually available.

------------------------------------------------------------------------
v2.6.0
------------------------------------------------------------------------
- Product reviews: the extension now scrapes Amazon and Flipkart reviews.
  Columns: Rating, Rating (number), Title, Review, Reviewer, Date, Verified,
  Helpful, Helpful (number), Variant, Product, URL. Reviews rank by helpful
  votes (then rating), and the analysis becomes review-aware (review count,
  average rating, % verified, rating breakdown, most-helpful review).
  Amazon uses stable data-hook selectors (reliable); Flipkart is best-effort
  (its class names are obfuscated) — report a page if a field is missed.

------------------------------------------------------------------------
v2.5.0
------------------------------------------------------------------------
- Smart column order: columns that have values come first; columns that are
  blank for this platform/output (e.g. Shares on Instagram/YouTube, or
  Likes/Comments on a basic reels scrape) are pushed to the end. Applies to
  the popup preview, CSV, and both Excel tabs. Paired columns (Views /
  Views (number)) stay together; Rank stays first.

v2.4.1
------------------------------------------------------------------------
- Fix: "Cannot access '_scriptBlobCache' before initialization" on some

------------------------------------------------------------------------
v2.4.0
------------------------------------------------------------------------
- Content Insights: the analysis now cross-analyses captions/content against
  engagement and surfaces PATTERNS, e.g. "Posts that mention an offer/
  discount get 2.1x more comments" or "Posts that mention <brand> get 4x
  more views". Dimensions include offers/discounts, festive themes,
  questions, hashtags, caption length, emojis, @mentions, calls-to-action,
  video length, OCR content type, and the most common caption keyword
  (surfaces brand/product/theme names). Works on views alone (basic scrape);
  likes/comments/shares comparisons unlock with Deep Scrape / LinkedIn.
  Each pointer shows the actual averages so it is transparent, not a guess.

v2.3.1
------------------------------------------------------------------------
- Exact first/last-post dates now use REAL deep scraping: the extension
  opens the first and last post each in a background tab, lets it render,
  and reads the exact date from the live page (no fetch/guesswork). This

v2.3.0
------------------------------------------------------------------------
- Exact date range: after a scrape, the extension fetches the precise
  posting date of the FIRST and LAST post (one quick request each) and
  uses them for the date range + "Date of first/last post". A callout
  warns it may take a few seconds; falls back to grid dates if it can't.
- Text insight pointers in the analysis (popup + Excel): most viewed,
  most liked, most comments, best engagement rate, longest/shortest video.
- Better video length: the first/last fetch also fills in duration when
  the grid didn't have it; duration now shows h:mm:ss for long videos.

HOW THE OCR BUNDLE IS BUILT
===========================

The offscreen OCR engine is PaddleOCR PP-OCRv4 (detection + recognition)
running on onnxruntime-web (WASM), fully on-device. No OpenCV: detection
post-processing is a light connected-components pass written in
ppocr-offscreen.mjs.

Source:   offscreen/src/ppocr-offscreen.mjs
Bundle:   offscreen/ocr.bundle.mjs   (loaded by offscreen/ocr.html)

To rebuild the bundle:

  npm install onnxruntime-web esbuild
  npx esbuild offscreen/src/ppocr-offscreen.mjs \
      --bundle --format=esm --platform=browser --target=chrome110 \
      --alias:onnxruntime-web=./node_modules/onnxruntime-web/dist/ort.wasm.bundle.min.mjs \
      --alias:onnxruntime-common=./node_modules/onnxruntime-web/dist/ort.wasm.bundle.min.mjs \
      --outfile=offscreen/ocr.bundle.mjs

Runtime assets (in ocr/):
  ch_PP-OCRv4_det_infer.onnx        detection model   (from @gutenye/ocr-models)
  ch_PP-OCRv4_rec_infer.onnx        recognition model (from @gutenye/ocr-models)
  ppocr_keys_v1.txt                 recognition dictionary (English/Latin + digits + symbols)
  ort-wasm-simd-threaded.wasm       onnxruntime-web WASM (from onnxruntime-web/dist)
  ort-wasm-simd-threaded.mjs        onnxruntime-web WASM loader glue

The bundle sets ort.env.wasm.wasmPaths to chrome.runtime.getURL('ocr/') and
numThreads = 1 (no worker threads, so no cross-origin-isolation requirement).
CSP: the bundle and the ORT glue contain no eval / new Function, so they run
under the manifest's "script-src 'self' 'wasm-unsafe-eval'".
